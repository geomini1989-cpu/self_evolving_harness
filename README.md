# Self-Evolving Harness (自我进化智能代理框架)

Self-Evolving Harness 是一个免训练（Training-Free）、具备自我进化能力的 LLM 业务编排框架。该系统通过内置的“病理诊断”与“根因分析”机制，能够在不微调大模型权重的条件下，自动化地对业务逻辑和系统技能进行“微补丁 (Micro-patching)”式的自我纠错与迭代。通过多模型路由策略与批处理机制，框架在保持强大进化能力的同时，极大地降低了系统延迟与 Token 消耗。

## 🎯 应用场景

本框架适用于**规则复杂、易发生长尾错误且需要持续调优**的自然语言处理与业务自动化场景，特别是：

* **智能客诉自动化打标与分发**：根据不断变化的业务口径和突发事件，自动抽象新的紧急策略并修复分类遗漏。
* **复杂非结构化数据解析**：如病历抽取、法律合同审查等，面对大模型由于“灾难性遗忘”或局部逻辑冲突导致的解析失败，自动反思并提炼通用规则。
* **动态业务系统接入**：作为一个轻量级的“操作系统”，能够根据用户意图动态挂载和调度对应的领域适配器与执行技能。

## 🚀 核心任务与特性

本框架严格围绕“冻结参数+框架自优化”的核心理念构建，包含以下核心任务能力：

* **支持自定义大模型接口及数据集**：支持灵活接入指定或自选的开源及商用大模型 API（绝对不进行任何权重微调），同时支持无缝加载对应领域的标准测试数据集或自定义的高质量验证集。
* **自迭代闭环引擎**：内置了完全自动化的“执行-评估-反思-进化”流水线。系统能够精准捕获执行失败的 Bad Case，通过轻量级模型的协同或规则引擎生成深度归因分析，并自动执行 Prompt 优化、Skill 文档的生成与淘汰、以及 Few-shot 示例动态注入等多种进化策略。
* **迭代可视化与指标输出**：集成监控大盘，提供详细的迭代轮数、当前技能库（Skill Bank）的实时状态，以及验证集/测试集核心指标（如准确率、F1 值、成功率等）的动态变化曲线，并支持输出量化指标进行多维度对比分析。
* **高可迁移性架构 (加分项)**：采用领域无关的底层抽象设计，通过配置不同的 Yaml 文件和适配器，技术方案可以实现“开箱即用”般的快速迁移，轻松应对同类不同的任务场景。

## 📂 核心文件与目录解析

项目代码结构围绕高度解耦的模块化设计，各个文件的主要职责如下：

### 1. 核心执行与入口

* **`main_loop.py`**: 框架的主控执行引擎，负责调度整个数据集的批处理执行流，并串联起大模型推理、结果评估、归因反思与技能进化的完整生命周期。


* **`requirements.txt`**: 运行环境依赖列表，包含 `openai`、`datasets`、`streamlit`、`plotly` 等核心支撑库。


* **`.env`**: 环境配置文件，用于安全隔离和管理 LLM 的 API_KEY 等敏感信息。



### 2. LLM 与核心底层 (core)

* **`core/llm_client.py`**: 负责所有 LLM API 的统一请求与多模型智能路由。内置缓存机制、Max Tokens 拦截与降级防护，通过动态切换“便宜模型 (cheap)”与“智能旗舰模型 (smart)”，以最小化 Token 损耗并加速迭代循环。


* **`core/evaluator.py`**: 数据解析与评估器，负责从模型输出的非结构化文本中精准剥离 JSON 数组，并基于 F1 等指标自动计算当前预测与 Ground Truth 的差异度。


* **`core/memory_bank.py`**: 系统的记忆中枢。负责管理和检索动态的 Few-shots 轨迹示例、读取当前生效的技能配置，并维护进化的版本记录。



### 3. 归因与进化引擎 (optimizer)

* **`optimizer/attributor.py`**: 病理归因模块。当系统出现判断失误时，负责接管 Bad Case，通过逻辑比对（如 TF-GRPO 机制）深度诊断模型执行失败的根本原因。


* **`optimizer/evolver.py`**: 自动进化模块。接收 `attributor.py` 的诊断结果，负责将碎片化的修复逻辑凝练总结，生成通用的微调补丁，并将其更新至全局的技能库中。



### 4. 记忆与技能库 (memory)

* **`memory/SKILL.md`**: 全局系统技能的物理载体，是大模型在进化过程中沉淀下来的业务规则“宪法”，在运行时会被动态检索和组装。


* **`memory/SKILL_backup.md`**: 技能库的安全备份，用于在进化发生退化（灾难性遗忘）时执行版本回滚策略。


* **`memory/latest_patch.json`**: 记录系统最近一次生成的逻辑微补丁数据，便于追溯优化轨迹。


* **`memory/examples.json`**: 持久化存储的高质量运行轨迹示例（Few-shots）。


* **`memory/metrics.csv`**: 全局核心指标日志，为数据可视化提供底表支撑。



### 5. 交互界面与配置 (dashboard / adapters)

* **`dashboard/app.py`**: 基于 Streamlit 搭建的交互式前端大盘，用于实时监控系统的自我进化过程、呈现 F1 变化曲线及技能库状态的对比。


* **`adapters/ticket_config.yaml`**: 任务场景适配器配置文件。定义了具体业务流（如客诉场景）的系统 Prompt 设定、期望的 JSON Schema 输出格式及任务元数据，是实现“高可迁移性”的核心组件。


* **`data/dataset.csv`**: 系统运行时加载的标准测试与验证数据集源文件。
